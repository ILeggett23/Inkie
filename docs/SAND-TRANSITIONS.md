# Sand transitions: architecture and qualification

## Audit before implementation

Baseline is PR14 head47d98893acac5508629cf01d16510a42cc837e24. `reader/src/main.cpp` enters the permit-gated direct session. Inkie is C++20, Qt6.8.2 Core/Gui, pure-C++ `ib::Canvas` painters and CPU RGB32 composition, not QML, QQuickItem or a Qt Quick scene graph. There is no QML damage stage to extend. `Shell` owns UI state, component painters and bounded `Change` damage; `Display::readerBoundary` consumes changes, `RefreshPlan` merges/subtracts regions, `RefreshController` governs regional updates and cleanup, and `VendorDisplay` alone calls the pinned EPFramebuffer boundary. Normal source acceptance is not physical panel completion. The plugin borrows RGB32 storage (1620x2160, stride1632); conversion footprints are aligned by the existing vendor adapter.

Pipeline: touch/Marker event → Shell state → component painter / canonical compose → Change regions → Display / RefreshController → existing vendor regional operation → controller/panel settlement (unobservable). Pen input uses the existing Marker/session/Engine path; display ownership, recovery, power and input transforms remain unchanged. Worker/helper preparation is asynchronous; foreground composition/submission stays serial. Orientation maps sheet/chrome coordinates to physical panel coordinates. Existing `localized::Reveal` is an optional three-phase, 18-dot margin adornment, not silhouette materialization. Its opt-in and tests stay intact when the new effect is off.

## Chosen strategy

Extend Shell's composition boundary with one deterministic C++ transition controller, not a second framebuffer owner. A bounded cropped snapshot of the previously submitted scene restores the background while a coherent directional field consolidates the actual difference silhouette into the current canonical component. Cache one snapshot and a fixed grain field; do not retain a second full-resolution final scene or run physics. Request at most one outstanding stage; missed stages are skipped. Existing regional UI quality is used first, because its RGB/removal contract is established; fast Pen updates band large areas and can reorder with quality cleanup. No new waveform experimentation is justified by the available evidence. Final/cancel cleanup stays regional and retains old colour classification through existing debt handling.

Full has four intermediate stages, Reduced two, Minimal one, Disabled immediate. These are software budgets, not physically tuned frame rates. Input, pending content work, orientation, scene identity changes, congestion and resource limits settle immediately. Large surfaces beyond the cropped budget appear immediately. Dismissal is optional; navigation never waits for it. First device qualification remains opt-in, disabled by default through Settings > Accessibility; Reduce motion overrides it. Existing panel/AI work begins immediately and input is never gated by decorative state.

Implementation and executed validation records follow below. No new tablet launch/install, live AI request, Companion deploy or PR merge is authorized by this specification.

## Implementation map and visual sequence

- `reader/src/sand_transition.{h,cpp}`: Qt-free shared state machine, directional coherent formation field, grain variants, deterministic reservoir anchored to actual component artwork, old/new difference silhouette, clipped composition and coverage-based source acknowledgements. One old-scene crop (<=8MiB) plus fixed arrays; no final-image cache. State is Hidden/Preparing/Revealing/Visible/Dismissing with a separate owed final cleanup. Starting another effect while one is owed is refused; newer UI is presented immediately.
- `sand_runtime.cpp`: shared component mappings, one attempt per explicitly opened surface, normal AI/note work starts independently. Directions: Tom/Notes enter from right; left tools/drawer from left (toolbar side respected); definition uses popup placement. Dismissal reverses the wind toward the departure side. Page turn, scrolling, reply streaming and individual cards/strokes never start it. Taller expanded/full-screen surfaces over the crop budget bypass it. Landscape currently bypasses decorative frames; existing landscape UI/input remains unchanged.
- `ux_shell.{h,cpp}`, `reveal_runtime.cpp`: canonical composition remains authoritative; one final overlay pass handles all compose branches, including cancellation/security. Input cancels decoration without changing tool semantics or adding an effect update during contact. After lift, current canonical pixels clean the entire owed footprint. Existing optional dot adornment is mutually exclusive and remains the off-feature behavior. Notes objects are created only by their original explicit actions.
- `ux_display.h`: sole refresh owner retained. Snapshot old source before canonical preparation; retain its richest pigment class across all stages. Regionally accepted source coverage retires stages; failed decorative requests retain ordinary cleanup debt and fall back without ending the app. Primary failures keep their existing handling. No new full-update permission, waveform number, pen mode, recovery behavior or display fence.
- `ui_prefs.h`, `library_view.*`, `ib/settings_screen.*`: optional backward-compatible `sandMode` field in existing version1 UI preferences; default0. Accessibility row cycles Off/Minimal/Reduced/Full, preserves other preferences and obeys Reduce motion.
- Tests/CMake/workflows: pure reproducibility/golden/budget/state tests and production Shell/Display/fake-vendor routes are part of host release, sanitizer and Ferrari target CI. Legacy reveal tests are also executed. The target baseline deliberately adds only Settings1005; existing target positions are unchanged.

Full: initial background → sparse incoming grains → granular concentration/surface islands → structural assembly → intact text/icons plus a few outer grains → normal canonical UI. Text/icons are withheld from partially formed interiors, then shown intact at consolidation. Reduced skips to concentration and consolidation; Minimal uses one structural stage then canonical content. CPU cost, busy work or deadline expiry skips remaining stages. The duration hint (180ms definition, 280ms other panels, capped350ms) is a software budget, not a measured panel timer. Large regions reduce Full to Reduced above400k pixels, then Minimal above900k; over2,097,152pixels is immediate. These are application budgets, not Xochitl or vendor thresholds.

## Observability and performance limits

Configure `-DINKBOUND_SAND_DEBUG=ON` for development-only SAND_START/SAND_STAGE stderr records: direction/scene, quality/reason, dirty bounds, stage stamp, mask generation/cache cost, last compose cost, actual regional requests/refusals, accepted logical source frames, skips and cleanup counts. Production does not print them. `sandMetrics()` exposes fixed-size counters without diagnostic pixels/file writes. Test frame images and their exact RGB goldens provide the offline visual view; no normal-operation debug overlay is introduced. Accepted frames/requests are software evidence only. No physical completion time is invented.

The local CPU harness profiles canonical buffer copies separately from added sand composition, snapshot/field generation and every stage. It also measures a1620x2160 canvas with the actual default lower-sheet footprint. Results are in the qualification report accompanying the draft PR; tests print median/p95/worst. The extra canonical preparation pass is app composition and must be counted in end-to-end device measurements; pure engine numbers do not include Qt helper work, vendor submission, input-to-optical latency or panel settlement. There is no current device before/after CPU/RSS, page-turn, handwriting or optical baseline for this new feature. ASan/UBSan and bounded allocations are not physical latency proof.

## Enable, disable, deployment and rollback

This feature ships **Off** for device qualification. In a subsequently approved installation, Settings → Accessibility → Wind-blown sand cycles the four modes. Reduce motion always overrides it. Off restores the established immediate UI / separately opted-in legacy adornment behavior without touching books, annotations or Notes. There is no launcher/environment modification. An app-only install requires fresh explicit approval, exact source/artifact/manifest verification, idle-stock checks, unchanged data hashes and a retained previous-app directory. The separately verified PR14 package remains the current installed rollback baseline; this feature has not been installed or launched.

Before enabling by default: authorize a candidate install/launch and compare actual Tom/definition/Notes/tools/drawer reveals and dismissals; repeat20 cycles; interrupt with pen/eraser/selection/navigation/orientation; compare coloured neighboring ink and erased areas after a quiet tail; measure request timestamps versus visible settlement with a camera if available; profile foreground CPU/RSS and input delay under load. Use fewer stages or Off if quality callbacks serialize too slowly or grains leave residue. No zero-ghosting or150–350ms physical completion claim is made. No Companion deployment, AI/provider request, stock binary/system-library replacement or firmware operation is needed.
